# Dashboard design system

## Page recipe

Every dashboard page extends `base::components.dashboard.layouts.master` and follows this order:

1. `x-dashboard.page-header` with a translated title, optional description, breadcrumbs, and primary actions.
2. Optional summary cards using `.dashboard-stats-grid` and `.dashboard-stat-card`.
3. Filters or the main workflow inside `.dashboard-card`.
4. Tables inside `.table-responsive`, with a translated empty state.

Complete screens live in their owning module. `Base` contains only the layout and reusable `x-dashboard.*` primitives.

## Shared tokens

Dashboard colors, radii, shadows, spacing, cards, headers, forms, tables, detail grids, and responsive rules are defined in `resources/css/app.css`. Reuse those tokens and Bootstrap 5 utilities before adding page-local CSS.

Use the existing Tabler icon mapping through `dashboard_icon_class()` or the shared button/link components. Do not add another icon or UI framework.

## Forms

- Every control has a visible translated label and a stable `id`.
- Render validation beside the related field.
- The primary submit action appears last; cancel uses the secondary label style.
- Destructive actions use the shared confirmation component.
- Forms must remain usable at mobile width without fixed pixel layouts.

## Tables and details

- Put row actions at the logical end and add accessible tooltips/labels.
- Use badges consistently for enum status values.
- Do not render an empty table body; use `.dashboard-empty-state`.
- Use `.dashboard-details-grid` for read-only records instead of one-off nested cards.

## JavaScript and assets

Shared JavaScript belongs in `resources/js` or the maintained Vuexy entry. Page behavior belongs in `@section('page-script')`. Vite inputs are explicit in `vite.config.js`; add an entry only when a current Blade view references it.

When changing a page, verify Arabic and English, RTL and LTR, mobile width, empty/loading/error states, keyboard focus, and the production build.

## Rendering safety

Blade's escaped `{{ }}` output is the default for database values, query input, flash messages, and editor content. Use `{!! !!}` only when the value is generated by the application and has already passed an explicit escaping or allowlist boundary. Pass server values into JavaScript with `@js`; never build a script literal with raw Blade interpolation.

## Component library

Build every dashboard screen from the shared `x-dashboard.*` components in `app/Modules/Base/Resources/views/components/dashboard` — do not hand-roll tables or forms.

- **List page** — `<x-dashboard.filter-bar>` (search + `<x-dashboard.filter-select>` dropdowns) above `<x-dashboard.table :paginator>` (a `head` slot, `@forelse` rows, `<x-dashboard.table-empty>` for the empty branch). Row actions: `<x-dashboard.actions>` wrapping `action-view` / `action-edit` / `action-toggle` / `delete-button`.
- **Create/edit** — `<x-dashboard.form-page :action :method :cancel :submit-label>` containing `<x-dashboard.field>` controls (text/email/number/date/select/textarea/checkbox/file, each with its own validation message).
- **Show** — `<x-dashboard.details>` with `<x-dashboard.detail :label :value>` rows.

Backend: declare `searchable`/`filterable` and call `applyDashboardFilters(...)` (`App\Modules\Base\Concerns\HandlesResourceQuery`) instead of hand-written `when()` chains. `Auth` users/managers/roles and `Notifications` are the reference screens.
